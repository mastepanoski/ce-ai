# Specification

## Requirement: Immediate orientation

- WHEN a visitor opens the README, THEN they SHALL see CE-AI described as an engineering workflow for coding agents before implementation-language or orchestration terminology.
- WHEN a visitor asks how CE-AI differs from Claude Code, Codex, OpenCode, or the Compound Engineering plugin, THEN the README SHALL provide a concise distinction and link to the detailed explanation.
- WHEN a visitor wants to try CE-AI, THEN the README SHALL provide a runnable, ordered path from install through project adoption and health verification.

## Requirement: Workflow comprehension

- WHEN a visitor views the public front door, THEN they SHALL see the simple sequence `Idea → Explore → Specify → Plan → Implement → Validate → Learn → Compound`.
- WHEN a visitor follows the detailed explanation, THEN it SHALL explain how accumulated learning helps future work.

## Requirement: Accurate attribution

- WHEN ODD is defined in a user-facing guide or the glossary, THEN it SHALL attribute ODD to Alan Buscaglia / Gentle AI and state that CE-AI adapts it rather than claiming its invention.
- WHEN Compound Engineering is described, THEN it SHALL identify EveryInc’s official plugin/methodology as the source and avoid suggesting CE-AI replaces it.

## Requirement: Upstream outreach

- WHEN maintainers read the prepared discussion draft, THEN it SHALL frame CE-AI as harness-level experimentation, ask for feedback and potential integration points, and avoid requesting addition to the upstream repository.
- WHEN the draft refers to upstream contribution, THEN it SHALL state that it is intended as an issue-first discussion rather than a PR.
