# Proposal: Automated Post-Merge OpenSpec Archival & Turn-0 Workflow Prescriptions

## Problem Statement
When AI agents (such as Claude Code, OpenAI Codex, OpenCode, Google Antigravity, or Cursor) complete a feature development cycle, merge the Pull Request into `main`, and return to the main branch, they frequently declare completion and halt without archiving the completed OpenSpec change package.

This behavior occurs across all projects adopting `ce-ai` due to three root causes:
1. **Incomplete Governance Directives**: Invariant #10 in `AGENTS.md` and the managed adoption blocks generated by `ce-ai init-prj` define post-merge cleanup strictly as git branch and remote pruning (`git pull`, `git branch -d`, `git fetch --prune`), completely omitting workflow FSM verification and OpenSpec package archival.
2. **Silent Turn-0 Resumption**: `ce-ai workflow resume` (the Turn-0 command mandated at every session start or context compaction) rehydrates git and manifest drift, but remains silent when completed, unarchived OpenSpec change packages reside in `openspec/changes/`.
3. **Passive Diagnostics**: `ce-ai workflow status` and `ce-ai doctor` emit passive warnings (`see openspec/changes/archive/README.md`) instead of prescriptive, actionable commands (`run 'ce-ai archive <name>'`).

## In-Scope
- Update Hard Invariant #10 in `AGENTS.md` and `render_block_content` in `src/commands/init_prj.rs` to mandate post-merge `workflow status` checks and automated archival.
- Update `ce-ai workflow resume` to actively detect completed OpenSpec change packages (all tasks checked) and emit high-visibility prescriptive directives instructing the agent to run `ce-ai archive <feature>`.
- Enhance `ce-ai workflow status` and `ce-ai doctor` to suggest the exact command `ce-ai archive <feature>`.
- Verify adoption block versioning and compatibility tests across `src/commands/init_prj.rs` and `tests/cli.rs`.

## Out-of-Scope
- Modifying the underlying archive compression formats (`.tar.gz` compaction).
- Silently archiving without git commit/PR when working in strict branch-protected environments.

## Success Criteria
- Running `ce-ai workflow resume` on a repository with completed unarchived OpenSpec packages surfaces an explicit `action required: run 'ce-ai archive <feature>'` notice.
- `ce-ai doctor` and `ce-ai workflow status` direct operators to run `ce-ai archive <feature>`.
- `AGENTS.md` and `init-prj` templates instruct all agents to verify clean workflow state and archive completed packages before halting.
