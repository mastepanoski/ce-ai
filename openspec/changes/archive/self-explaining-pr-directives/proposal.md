# Proposal: Self-Explaining PR Directives & Upfront Review Readiness in AGENTS.md

## Problem Statement
When AI agents (such as Claude Code, OpenAI Codex, OpenCode, Google Antigravity, or Cursor) operate in repositories adopted by `ce-ai`, they execute the 7-stage Compound Engineering development cycle and create Pull Requests (Stage 7). However, PR descriptions generated by agents frequently suffer from common AI failure modes:

1. **Diff Paraphrasing instead of Decision Rationale**: PR bodies restate what code changed rather than explaining *what alternatives were explored and ruled out* and *which specific project rule, invariant, or architectural constraint decided the chosen approach*.
2. **Missing Upfront Evidence**: PRs are opened without attaching empirical validation proof (test run summaries, CLI logs, reproduction traces, or browser check results), forcing human reviewers to ask for verification after the fact.
3. **Premature Review Requests**: PRs are marked ready for human review before all automated verification gates (formatting, linter, tests, headless browser checks, E2E) have run and passed cleanly.
4. **Lack of Domain Reviewer Routing**: PRs are created without identifying or notifying the specific domain owners or subsystem leads responsible for the affected area.

## In-Scope
- Update `render_block_content` in `src/commands/init_prj.rs` across `Full`, `Minimal`, and `Orchestrator` adoption tiers to inject explicit PR & Review Readiness directives ("A Change That Explains Itself", upfront evidence in collapsible `<details>` blocks, pre-review automated check gates, and reviewer routing).
- Bump `BLOCK_VERSION` from 5 to 6 in `src/commands/init_prj.rs` and lockstep fixtures in `tests/cli.rs`.
- Update repository root `AGENTS.md` and `CONTRIBUTING.md` with:
  - Stage 7 PR & Review Readiness Directives.
  - Sizing guidance clarifying that collapsible evidence blocks in PR descriptions do not count against code LOC budgets, while affirming that the 400 LOC code review boundary must NOT be relaxed because atomic PRs are a prerequisite for readable self-explaining changes.
- Update repository root `GEMINI.md` and `AGENTS.md` managed blocks.

## Out-of-Scope
- Modifying underlying git hook execution binary scripts.
- Implementing automated GitHub review bots or automated PR approval bots.
- Altering the git commit-signing or SSH transport layer.

## Success Criteria
- Running `ce-ai init-prj` outputs managed blocks containing the new PR & Review Readiness directives.
- `ce-ai doctor` and `ce-ai status` correctly classify v5 blocks as `StaleVersion` and recommend upgrading via `ce-ai init-prj`.
- Unit tests, CLI tests, and E2E gates pass with 100% green status.
- SemVer bumped to `v1.69.0` and `CHANGELOG.md` updated.
