1. Diagnóstico del Problema y Threat Model en Coding Agents

Los agentes de codificación autónomos (Claude Code, Gemini CLI, Cursor, OpenCode, Codex, Copilot) operan leyendo archivos locales del repositorio, logs de ejecución, fixtures de pruebas, volcados SQL y salidas de terminal. En entornos empresariales y proyectos del mundo real, esto expone cuatro vectores críticos de fuga de información hacia los proveedores de LLM en la nube:

  • Vector 1 (LLM Context Egress): Comandos como git diff, lectura de archivos .env o inspección de logs de pruebas pueden arrastrar PII (Personally Identifiable Information: emails de usuarios, nombres, teléfonos, tarjetas de crédito de staging, números de seguridad social) hacia el prompt del modelo externo.
  • Vector 2 (Infracción de GDPR / HIPAA / Leyes de Privacidad): El envío inadvertido de datos personales no anonimizados hacia APIs de terceros en Estados Unidos u otras regiones geográficas constituye una transferencia internacional no autorizada bajo GDPR (Arts. 44-49) y una violación de HIPAA § 164.502.
  • Vector 3 (Controles ISO/IEC 27001:2022 y ISO 27701): La norma ISO 27001 exige controles mecánicos específicos:
    • Control A.8.11 (Data Masking): Los datos sensibles deben ser enmascarados de acuerdo con la política de control de acceso y requisitos legales aplicables.
    • Control A.8.12 (Data Leakage Prevention): Medidas de DLP aplicadas a canales de salida (en este caso, tráfico HTTPS de agentes hacia APIs de LLM).
    • Control A.8.24 (Use of Cryptography): Manejo seguro de claves y encriptación de datos en tránsito.
  • Vector 4 (Publicación de Trazas y Bug Reports): Funcionalidades como ce-ai report-bug generan reportes hacia GitHub Issues públicos; si el filtrado es incompleto, fragmentos de tokens, rutas internas o PII del desarrollador quedan expuestos permanentemente en la web.

2. Anatomía Técnica de Microsoft Presidio

Microsoft Presidio es una suite de código abierto desarrollada en Python para la detección y de-identificación de PII en texto estructurado y no estructurado. Su arquitectura consta de dos motores principales:

Componentes Clave de Presidio Python / spaCy / Docker
  • Presidio Analyzer: Utiliza una combinación de expresiones regulares, sumas de comprobación (checksums de tarjetas de crédito vía algoritmo de Luhn, validadores de IBAN) y modelos de NLP / Named Entity Recognition (spaCy o Hugging Face Transformers) para detectar entidades contextuales (PERSON, LOCATION, EMAIL, PHONE_NUMBER, etc.).
  • Presidio Anonymizer: Toma los hallazgos del analizador y aplica operadores: Redactar (eliminar), Reemplazar (ej. <EMAIL_ADDRESS>), Enmascarar (ej. ****-1234), Hashear (SHA-256) o Cifrar/Descifrar reversiblemente con AES.
  • Presidio Image Redactor: Combina OCR (Tesseract) con el analizador para censurar PII visual en capturas de pantalla o PDFs.
Huella Operativa: Presidio requiere Python 3.9+, un runtime de spaCy o Transformers (~500 MB – 2 GB en disco y memoria RAM), y típicamente se despliega como servicio web / contenedor Docker (mcr.microsoft.com/presidio-analyzer y presidio-anonymizer).

3. Ideas Rechazadas y Razonamiento de Descarte

De acuerdo con los principios de ce-ideate ("Generar muchas -> criticar todas -> explicar solo sobrevivientes"), el valor de la ideación radica en el descarte explícito de alternativas subóptimas:

❌ Idea Rechazada 1: Embeber Presidio directamente en el binario de ce-ai

Por qué se descarta: ce-ai es un binario nativo único en Rust de ~10 MB, compilado estáticamente con musl en Linux, Mach-O nativo en macOS y MSVC en Windows, con tiempos de inicio de 10-20 ms. Presidio depende de Python, C-bindings de PyTorch/spaCy y cientos de megabytes de pesos de modelos NLP. Forzar un runtime de Python dentro del binario Rust de ce-ai destruiría su portabilidad multiplataforma, inflaría el instalador a >1.5 GB y ralentizaría la CLI en dos órdenes de magnitud.

❌ Idea Rechazada 2: Hacer de Presidio un prerequisito obligatorio / bloqueante en ce-ai doctor

Por qué se descarta: Viola directamente el Invariante 6 de AGENTS.md (No Semantic Authority). ce-ai no debe imponer servicios pesados externos o herramientas de terceros que Compound Engineering no exige. Imponer Docker y Presidio a desarrolladores que escriben microservicios en Go o CLIs en Rust que no procesan PII introduciría fricción y rechazo inmediato.

❌ Idea Rechazada 3: Enrutamiento de todos los prompts de los agentes a través de un proxy local obligatorio gestionado por ce-ai

Por qué se descarta: Muchos desarrolladores y empresas utilizan LLMs locales (Ollama, LM Studio) o túneles corporativos VPN con certificados mTLS customizados. Forzar un proxy intermediario obligatorio añade puntos únicos de fallo de red, complejidad de configuración de certificados SSL/TLS y latencia en cada turn del agente.

4. Ideas Sobrevivientes Seleccionadas (Top Survivors)

Tras el filtrado de restricciones de rendimiento, huella de memoria y arquitectura, las siguientes tres direcciones complementarias emergen como las más sólidas:

1. Motor PII Nativo en Rust dentro de ce-ai (Zero-Python DLP)
Sobreviviente #1 Core Rust / Sub-1ms
Concepto & Enfoque
Implementar en ce-ai un submódulo ligero en Rust (src/security/pii.rs) inspirado en las reglas deterministas de Presidio, pero sin requerir Python ni modelos pesados. Utiliza expresiones regulares precompiladas y validadores de checksums matemáticos:
  • Tarjetas de Crédito: Detección de patrones Visa, Mastercard, Amex con validación estricta de algoritmo de Luhn (evita falsos positivos con IDs numéricos).
  • Emails y Teléfonos Internacionales: Expresiones regulares conformes a RFC 5322 y formato E.164.
  • Documentos de Identidad & SSN: Formatos estructurados (US SSN, DNI/NIE español, CIF, IBAN con checksum ISO 7064).
  • Secretos y Tokens de Autenticación: Ampliación del motor actual de src/decisions/risk.rs (JWTs, Bearer tokens, GitHub PATs, AWS Access Keys, OpenAI/Anthropic sk- keys, certificados PEM).
Dónde se Aplica Mecánicamente
Se conecta automáticamente a:
  1. ce-ai report-bug: Sanitización automática profunda antes de publicar issues.
  2. ce-ai guard: Bloqueo o advertencia si un comando a ejecutar en el terminal contiene PII en claro.
  3. Pre-commit gate (scripts/install.sh / .githooks/pre-commit): Bloqueo en staging si se detectan credenciales o PII cruda.
Ventaja Competitiva: Ejecución en < 0.5 milisegundos en memoria, 0 MB de dependencias adicionales, 100% nativo y multiplataforma. Cubre el 90% de los incidentes de fuga de datos estructurados para ISO 27001 (Control A.8.11).
2. Diagnóstico Heurístico y Auditoría ISO 27001 en ce-ai doctor
Sobreviviente #2 Advisory / Governance
Concepto & Enfoque
Extender ce-ai doctor (similar a las heurísticas de QA skills que acabamos de lanzar) con una comprobación de Postura de Privacidad y Cumplimiento:
  • Detección de Esquemas Sensibles: Si el repositorio contiene modelos o migraciones SQL con campos sensibles (ej. users.email, ssn, credit_card, patients, billing, directivas de telemetría).
  • Aviso de Gobernanza (Non-blocking): doctor-info: privacy: detected PII-handling schemas in project; for ISO 27001 / GDPR compliance, consider enabling local PII masking or deploying an AI Gateway with Microsoft Presidio (run 'ce-ai privacy guide').
  • Checklist de Cumplimiento ISO 27001 / ISO 27701: ce-ai audit --compliance iso27001 genera un reporte visual de los controles mecánicos presentes en el repo (redacción de secretos, atomic writes, manifest SHA256, branch protection).
Alineación con Invariantes: Es 100% consultivo e informativo; no bloquea el flujo de trabajo de desarrolladores que no manejan PII, pero proporciona una guía auditable inestimable para empresas reguladas.
3. Arquitectura de Referencia: AI Privacy Gateway (LiteLLM / Presidio)
Sobreviviente #3 Enterprise Blueprint
Concepto & Enfoque
Para organizaciones con requerimientos estrictos de NLP / Named Entity Recognition no estructurado (donde los nombres propios de personas como *"Juan Pérez dijo en el ticket #123"* deben ser anonimizados mediante IA), la solución arquitectónica correcta **no es meter Presidio en la CLI**, sino situar Presidio en un AI Privacy Gateway intermedio:
  • Proveer un comando / template: ce-ai privacy gateway-preset o una receta Docker Compose en docs/arch/contracts/privacy-gateway.yaml.
  • El gateway (ej. LiteLLM Proxy con el plugin oficial de Presidio o Portkey) actúa como reverse-proxy para Claude Code, OpenCode, Cursor y Gemini.
  • El gateway enmascara la PII antes de que el texto salga de la red corporativa y la des-enmascara opcionalmente al recibir la respuesta del modelo, cumpliendo de forma determinista con ISO 27001 Control A.8.12.
Transparencia Multi-Harness: Al operar a nivel de proxy HTTP (vía variable ANTHROPIC_BASE_URL o OPENAI_BASE_URL), protege a todos los agentes sin necesidad de reprogramar cada harness individualmente.

7. Plan de Acción Recomendado y Handoff

Veredicto y Recomendación Estratégica

No "poner" Presidio en el binario; implementar la estrategia dual Nativa + Gateway:

  1. Paso 1 (Corto Plazo - Core Rust): Robustecer el motor nativo de ce-ai (en src/decisions/risk.rs y src/source/bug_reporter.rs) incorporando validación matemática de Tarjetas de Crédito (Luhn), números de teléfono internacionales, IBANs y emails estándar. Proporciona protección sub-milimétrica sin inflar el binario.
  2. Paso 2 (Corto Plazo - Diagnóstico & Gobernanza): Añadir a ce-ai doctor y ce-ai init-prj una comprobación no bloqueante similar a la de QA skills: cuando el proyecto maneje bases de datos con PII o esté etiquetado para ISO 27001, emitir un doctor-info: sugiriendo evaluar Presidio en el AI Gateway de la empresa.
  3. Paso 3 (Mediano Plazo - Blueprint Empresarial): Documentar formalmente en docs/arch/contracts/ una arquitectura de referencia para desplegar un AI Privacy Gateway corporativo (LiteLLM + Microsoft Presidio Container) para organizaciones que necesiten enmascarar nombres propios en lenguaje natural antes de invocar APIs de LLM.
Handoff Sugerido: Esta evaluación técnica puede transicionar directamente a ce-brainstorm para formalizar los requerimientos del motor de enmascaramiento de PII nativo en Rust (Paso 1) y las comprobaciones de ce-ai doctor (Paso 2).
